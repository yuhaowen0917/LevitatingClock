# TickSync

抢票 / 秒杀场景下的标准时间校准工具。把手机时钟对齐到授时中心或**票务平台自己的服务器时间**，用悬浮窗常驻显示，并在开抢前给出倒计时。

## 它解决什么问题

抢票失败的原因里，有两个和"你看到的时间"直接相关：

1. **本机时钟不准**。手机系统时间常见偏差数百毫秒到数秒，而热门场次的开抢判定就发生在那一两秒内。
2. **倒计时的参照物错了**。平台页面上"距开抢还有 x 秒"是按**平台服务器**的时间算的。就算你的手机是全球最准的时钟，只要平台服务器慢 800ms，你也会比预期晚 800ms 出手。

TickSync 同时处理这两件事：把时间校准到标准时间，并允许你直接对齐到目标平台的时间。

> 至于你到票务服务器的网络延迟（通常 20~200ms），那是物理限制，任何软件都消除不了。详见文末「精度与局限」。

## 功能

### 多源时间校准

时间源分三类，可在「时间源」页自由增删改、按需开关：

| 类型 | 说明 | 预置 |
| --- | --- | --- |
| **NTP** | UDP 123 授时协议，四时间戳法，毫秒级 | 国家授时中心、阿里云、腾讯云（默认启用）<br>公共池（默认停用） |
| **平台接口** | 直接问平台自己的服务器 | 淘宝/天猫、京东、苏宁易购（毫秒级）<br>大麦、猫眼（取响应头 `Date`，秒级）<br>**全部默认停用** |
| **设备时间** | 本机系统时间，不参与校准 | 固定存在，可停用但不可删除 |

平台源默认关闭：它们是各平台的业务接口，只在用户明确开启后才发起请求，避免无谓的后台轮询触发风控。

**融合策略**：并发探测所有已启用源 → 计算 offset 粗中位数 → 剔除与中位数偏差超过 150ms 的离群样本 → 剩余样本取中位数作为最终结果 → RTT 最小的源标记为"本次采用的源"。

设备时间的 offset 恒为 0，丢进中位数会系统性拉偏结果，因此它**不参与融合**：只在所有网络源都失败时降级兜底，并如实显示为「设备时间（未校准）」。

### 悬浮窗

- 三档尺寸：`HH:mm:ss` / 含毫秒 / 含倒计时与状态
- **按下即拖**，不需要长按等待
- 单击展开操作面板（尺寸 / 打开 / 关闭），无操作 4 秒自动收起；双击直接切档
- 拖动到贴近屏幕边缘会自动吸附并降低透明度
- **穿透模式**：窗口不参与命中测试，覆盖区域内对下层应用零干扰
- 划掉应用即关闭悬浮窗

### 倒计时

- 目标时刻为「每日重复的时分秒」，贴合"每天 10:00 开抢"的心智，一次配置长期可用
- 时钟页卡片与悬浮窗同步展示
- 最后一分钟转橙、最后十秒转红——归零前你的目光在抢票按钮上，余光只感知得到颜色
- 归零时震动提醒一次，并自动转入下一轮

## 工作原理

### 时钟引擎

**不直接显示 `System.currentTimeMillis() + offset`**。系统时钟可能被自动校时或用户手动修改而跳变，逐帧重算会让秒位跳帧甚至倒走。

正确做法是「锚点 + 单调时钟推进」：每次校准成功时记录一对锚点——当时的 `SystemClock.elapsedRealtime()`（单调，不受系统时间调整影响）与当时的标准时间戳。之后任意时刻：

```
标准时间 = 锚点标准时间 + (当前 elapsedRealtime - 锚点 elapsedRealtime)
```

设备重启后 `elapsedRealtime` 归零，旧锚点失效，因此用持久化的 offset 重建锚点；本次运行期内依然单调不跳变，跨重启的准确性由 offset 的新鲜度决定（界面会显示"上次校准于 x 分钟前"）。

### 平台时间源的取值

按精度从高到低回落：

1. **响应体中的 13 位、首位为 1 的整数**——各平台的时间接口普遍返回毫秒时间戳，精度与 NTP 同级；
2. **响应头 `Date`**——只有整秒精度，但任何 HTTP 接口都有，作为兜底。

刻意**不做**"与本地时间比对"的合理性校验：本机时钟本就可能是错的，那正是本应用要解决的问题，拿它去否定服务器时间会形成死循环。误匹配的漏网之鱼交给融合层的中位数与离群剔除兜底。

## 构建

要求：JDK 17、Android SDK（`local.properties` 中的 `sdk.dir`）。

```bash
./gradlew assembleDebug
```

技术栈：

| 项 | 版本 |
| --- | --- |
| Kotlin | 2.0.20 |
| AGP | 8.5.2 |
| Gradle | 8.7 |
| Compose BOM | 2024.09.02 |
| minSdk / targetSdk | 26 / 34 |

网络层未引入第三方库：NTP 用 `DatagramSocket` 手写 SNTP 客户端，HTTP 用 `HttpURLConnection`。

### 开发环境提示

- **国内网络**：Gradle 发行版走腾讯云镜像，依赖走阿里云镜像，见 `settings.gradle.kts` 与 `gradle/wrapper/gradle-wrapper.properties`。
- **Windows 中文用户名**：Kotlin 编译守护进程在跨进程传递路径时会把中文转义为 `uXXXX` 导致 Compose 编译插件路径失效，因此 `gradle.properties` 中已改为进程内编译（`kotlin.compiler.execution.strategy=in-process`）。
- **Gradle 源码包**：Android Studio 索引 Gradle API 时使用的 `gradle-8.7-src.zip` 在 Gradle 8.7 里是硬编码地址（`services.gradle.org` → 重定向到 GitHub Releases），无法通过配置换镜像。`gradle-wrapper.properties` 中记录了绕开方式。

## 精度与局限

校准消除的是**本机系统时钟**的误差。它消除不了：

- **你到服务器的网络延迟**（通常 20~200ms）。你在倒计时归零时点击，请求到达服务器仍会晚一个往返延迟。建议结合界面上显示的网络延迟值预留提前量。
- **秒级源的量化误差**。取 `Date` 响应头的源精度是整秒，用于抢票时请优先选择毫秒级源，界面会在精度低于毫秒时标注「秒级」。
- **平台接口的不确定性**。预置的平台地址均为公开时间接口，非官方 API，可能随时变更或被风控。建议使用前先单独开启一个源，用「立即校准」验证能出结果。
- **本机晶振漂移**（通常每天 < 1 秒），由定时自动校准修正。

## 隐私

- 不收集任何个人信息
- 仅访问你在「时间源」页显式启用并配置的地址
- 不读取、不注入任何第三方应用的数据
- **不提供自动化点击能力**，只显示时间
